Resumen ejecutivo

◈
Objetivo real del módulo: No es captar prestadores. Es crear confianza, validar reputación, generar recomendaciones, retener al prestador y producir efecto de red. El KPI es que el prestador diga: "SERVY me consigue trabajo" — no "SERVY tiene mis datos".
◉
Hoy
Registro en 4 pasos → silencio. Sin retención, sin panel, sin presencia.
◈
Meta
Identidad digital completa: dashboard, perfil público, reputación y loop viral.
⬡
Ventaja
Muchos prestadores no tienen web, Maps ni tarjeta digital. SERVY llena ese vacío.
↻
Efecto
Cada prestador que comparte su perfil trae nuevos clientes y recomendadores.
◆
Diferenciador frente a competidores (Habitissimo, Thumbtack, TaskRabbit): SERVY apuesta a confianza vecinal + WhatsApp + recomendaciones humanas. En LATAM eso pega más que un marketplace anónimo.
01

Estado actual

El formulario de registro funciona. Capta micro-compromisos. Pero termina en una pantalla de "te contactamos" sin continuidad real.

Paso Título Datos que se piden Estado
1 Activá tu perfil Nombre completo, WhatsApp ✓ OK
2 ¿Qué ofrecés y dónde? Categorías de oficio (14 opciones), zona geográfica, radio ✓ OK
3 Info adicional (opcional) Foto de perfil, email, descripción (280 chars) Mejorable
4 Términos Aceptación legal ✓ OK
Post Pantalla de éxito "Te contactamos por WhatsApp" — sin panel, sin perfil, sin seguimiento Gap crítico
⚠
Problema principal: El prestador siente que "dejó datos y desapareció". No hay loop de retención, no hay incentivo para volver, no hay panel donde ver si está siendo contactado. El registro muere en el paso 4.
02

Flujo rediseñado

El registro es solo la puerta de entrada. El valor real empieza después, con un onboarding progresivo que transforma al prestador en un perfil digital activo.

1
Registro rápido (4 pasos actuales)
Nombre, WhatsApp, oficio, zona. Bajo fricción. Objetivo: micro-compromiso. No pedir más de lo necesario en esta etapa.

2
WhatsApp onboarding automático
Mensaje de bienvenida inmediato vía n8n. Barra de progreso de perfil. Cada mensaje explica el beneficio concreto de completar ese campo.

Completado progresivo del perfil
Dashboard con barra de completitud. Gamificación suave: cada campo desbloqueado sube el porcentaje y mejora la visibilidad en búsquedas. El prestador avanza a su ritmo.

03

Niveles de confianza

Sistema de badges progresivos con conceptos humanos, no artificiales como "Gold/Platinum". Cada nivel tiene requisitos claros y beneficios concretos de visibilidad.

◌
Registrado
Completó el formulario básico. Datos mínimos: nombre, WhatsApp, oficio, zona.
Nivel base
✓
Perfil Completo
Más del 60% de campos del perfil completados. Foto, descripción, horarios, rubros secundarios.
+10% visibilidad
⭐
Recomendado
3 o más recomendaciones reales de clientes verificados. Promedio ≥ 4 estrellas.
+25% visibilidad
🛡
Verificado
DNI validado (frente + dorso) y teléfono WhatsApp confirmado activo.
+35% visibilidad
🏆
Destacado SERVY
SERVY Score ≥ 75. Mínimo 10 reseñas, promedio ≥ 4.5, verificado, perfil 80%+.
Aparece primero
🌟
Comunidad SERVY
Activo 12+ meses, 20+ reseñas, score ≥ 85, cero reclamos graves. Insignia especial.
Top destacado
◈
Clave psicológica: El prestador NO siente que "SERVY usa sus datos". Siente que "SERVY me ayuda a conseguir trabajo". Los niveles deben comunicarse siempre como beneficios, nunca como requisitos. "Completá tu foto y llegás a más clientes" — no "te falta la foto".

Schema Supabase

Extensiones sobre la tabla prestadores existente. Ejecutar en Supabase SQL Editor después de correr la migración base.

-- ─── Extensión tabla prestadores ─── ALTER TABLE prestadores ADD COLUMN IF NOT EXISTS -- Identidad extendida selfie_validacion_url text, slug text UNIQUE, -- Profesional subrubros text[], matricula text, tiene_seguro bool DEFAULT false, herramientas_especiales text, -- Operación horarios jsonb, -- {"lun":"8-18","sab":"8-13"} acepta_urgencias bool DEFAULT false, emite_factura bool DEFAULT false, medios_pago text[], -- ["efectivo","transferencia","mercadopago"] tiempo_respuesta_horas int, -- promedio calculado -- Marketing instagram_url text, facebook_url text, web_propia_url text, portfolio_url text, -- Métricas (calculadas por n8n o edge functions) vistas_perfil int DEFAULT 0, clicks_whatsapp int DEFAULT 0, servy_score int DEFAULT 0, nivel_confianza text DEFAULT 'registrado'; -- ─── Tabla reseñas ─── CREATE TABLE IF NOT EXISTS resenas ( id uuid PRIMARY KEY DEFAULT gen_random_uuid(), prestador_id uuid REFERENCES prestadores(id) ON DELETE CASCADE, score int CHECK(score BETWEEN 1 AND 5), comentario text, nombre_cliente text, tel_cliente text, verificado bool DEFAULT false, creado_en timestamptz DEFAULT now() ); -- Índice para slug (lookup por URL pública) CREATE INDEX IF NOT EXISTS idx_prestadores_slug ON prestadores(slug) WHERE slug IS NOT NULL; -- Índice para score (ordenar búsquedas) CREATE INDEX IF NOT EXISTS idx_prestadores_score ON prestadores(servy_score DESC) WHERE estado = 'activo';
⚠
Recordatorio: La migración base (supabase_migration_v1.sql) que hace DROP + CREATE de la tabla prestadores todavía está pendiente de ejecutar. Correr esa primero antes de aplicar estas extensiones. También actualizar los webhooks n8n servy-prestador y servy-propuesta para el nuevo schema.
